How to read this report

Rounded counts: k = thousand; M = million. Hover over a record count for its exact value. Earlier runs, including older reference sizes, remain in the source CSV; this page selects the latest results for each input size.

Outcomes: existing match, no existing match, review and rejected are shares of the original input. Master output retains all reference masters and adds resolved new customers, so it can exceed the input count.

Memory: process RAM covers Python, DuckDB and other resident process allocations. DuckDB tracked memory covers its buffer manager; Python traced memory covers allocations traced during a stage. These values do not add up to total process RAM. The configured budget is a limit, not reserved RAM.

Threads and disk: total/active process threads include Python and monitoring, not just DuckDB workers. CPU capacity is CPU core-equivalents divided by configured threads, so it can exceed 100%. Saved data includes all Parquet inputs, intermediates and outputs. Zero temporary disk means no spill was observed in the samples.

Timing and sampling: separate-command timings use their measured command durations; combined time adds generation and ETL without manual waiting. For a combined command, stage details separate the work and pipeline time sums the five ETL stages. Memory/thread peaks are observed samples and may miss short activity, especially in sub-second stages.

Source: stats.csv · Static snapshot; refresh with python build_benchmark_report.py. No ETL logic or source statistics are changed.
